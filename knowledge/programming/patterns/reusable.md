# 再利用可能な成功パターン登録簿 (reusable patterns)

> [[claude_mistakes]] の「陽」の対。あちらが **失敗** を資産化するなら、こちらは **3回以上うまくいった型** を拾って再利用資産に昇格させる登録簿。
>
> 背景: YD の Vault は失敗の資産化 (mistakes 40件・頻度タグ・統計・ε モード) は厚いが、成功側は decisions/knowledge に散発記録するだけで「昇格ルート」が無かった。2026-07-09 Fable5記事の Skills自動蓄積パターンを Max20x完結に翻訳して新設。
>
> **縛り**: API 自動生成はしない ([[2026-05-19_API依存撤廃_Max20x完結化]])。月次メンテで人手 (Claude Code セッション内) で拾う運用。

## 🔁 昇格ルート (どう運用するか)

1. **拾う**: 月次メンテで `log.md` / `decisions/` を眺め、「同じ型を3回以上、成功率高く回した」ものを検出。
2. **判定**: 再現価値があるか (次にゼロからやる人が迷うか)。1〜2回のまぐれは登録しない。
3. **昇格先を選ぶ** (3択):
   - **① Vault テンプレ化** — `templates/` に雛形化 (decision / knowledge の定型など)
   - **② knowledge snippet 化** — この登録簿 or `knowledge/<領域>/` に手順ノート化
   - **③ Claude Code skill 化** — `skill-creator` スキルで本物の skill に (キーワード自動ロード)
4. **記録**: 下の「登録済みパターン」に1エントリ追加。昇格先へのリンクを貼る。

## 📋 エントリ・フォーマット

```
### P-<番号>. <一行サマリ> (登録: YYYY-MM-DD、成功回数: N)

**状況/トリガー**: <どういう時に使う型か>
**なぜ効いたか**: <この型が成功する理由>
**再利用テンプレ**: <コマンド / 手順 / プロンプト / リンク>
**昇格先**: template / knowledge / skill (どれに落としたか + リンク)
```

## ✅ うまく行ったこと (この登録簿の運用について)

- mistakes/ という「陰」の資産化構造が既にあるので、対になる「陽」の構造をコピーすればよく、設計コストが低い
- 昇格先の受け皿 (templates / knowledge / skill-creator) が既に全部揃っている

## ❌ 詰まったこと

- 該当なし (新設直後、運用実績ゼロ)。想定リスク: 月次メンテで拾うのを忘れると死蔵する → CLAUDE.md の月次メンテ項目に組み込んで強制する

## 📋 次回同じことをするときのチェックリスト

- 月次メンテ時、`log.md` を「同じ作業3回以上」の観点で1回スキャンする
- まぐれ (1〜2回) は登録しない。再現性が判定基準
- 昇格先は「次に使う人が一番早く再利用できる形」で選ぶ (使い捨てなら snippet、頻用なら skill)
- 登録したら [[claude_mistakes]] と同様、出典 (どの log/decision から来たか) を明記
