# Remotion の映画式エンドロールでカードに写真/動画を出すときの設計

プペル エンドロール (`ALL WORKs/プペル_エンドロール素材/remotion/`) で、右にクレジットが流れ左にポラロイド風カードが切り替わる形を作った際の知見。同じ構造を次に作るとき、ここに書いた4点を最初に決めれば作り直しが減る。

## そもそも何点入るのかを先に計算する

ロールが等速で流れる以上、1枠のカードが画面に居る時間は幾何で決まる。ここを計算せずに「1点2.4秒で4点」と決めると、見えない位置に素材を置くことになる。

    カードの絶対Y = 1080 - SPEED × localT + 20     (localT = そのブロックのSequence開始からの秒数)
    カードが少しでも見える   : localT 0.14 〜 10.36
    カードが完全に見える     : localT 2.95 〜 7.55   ← 実質ここだけが勝負

プペルの実測は SPEED = 145.7px/s、カード高 410px で、完全表示は **4.6秒しかない**。1点2.4秒なら完全に見せられるのは2点弱。4点入れても3〜4点目は出入りの途中にしか映らない。

そのうえで切替時刻は等間隔にせず、点数ごとに決め打ちした。

| 点数 | 切替時刻 (秒) | 意図 |
|---|---|---|
| 2 | 0, 4.5 | 2点目を完全表示ゾーンいっぱいに乗せる |
| 3 | 0, 2.6, 5.3 | 2点目と3点目を完全表示に |
| 4 | 0, 1.9, 4.1, 6.3 | 1点目を短くして残り3点を後ろへ寄せる |

## 落とし穴4つ

### 1. 動画はSequenceで包まないと頭出しできない

`OffthreadVideo` の再生位置は親Sequenceの時間軸で決まる。カード内で3点目に置いた動画は、ロール開始から7秒経った時点で表示されるので **動画の7秒地点から再生される**。ベストシーンを切り出しても意味がない。表示開始フレームを `from` にしたSequenceで包んで初めて頭から出る。

### 2. 最後の点を保持するとクリップが尺切れして黒くなる

「ループさせず最後の1点を保持」に変えた途端、最後が動画の13枠でカードが1.5〜2秒間、金の罫線だけの黒箱になった。保持は10.6秒まで続くのにクリップは3.1秒しかないため。`<Loop durationInFrames={クリップ長}>` で包んで解決。なお使用バージョンの `OffthreadVideo` に `loop` prop は無い (型エラーになる)。

### 3. 横長カードに縦素材を入れると顔が切れる

540×380 に `object-fit: cover` で縦写真を入れると高さの4割が落ちる。中央固定では後列の顔が目の上で切れたり、逆に天井のダクトだけの帯になる。素材ごとに `object-position` を持たせ、`50% 38%` のように個別調整した。ただし **4:3の横位置素材では上下6%しか削られないので object-position はほぼ効かない**。この場合は元画像を先にクロップして作り直すしかない。

### 5. 最後の点をループで保持すると「ワープ (巻き戻り)」に見える

クリップ長 < 保持時間のとき、ループの切れ目でクリップが頭に戻る。これが「ワープ」として視覚的に目立つ。対処: クリップを保持時間+余裕 (0.5〜1秒) まで切り出し直す。全クリップについて「clip長 > 最大保持時間」を数値で検証してから確認レンダーする。

プペルの場合: 枠ごとの最大保持時間を Python で計算 → 必要最低尺を算出 → ffmpeg で再切り出し → warp_sheet.jpg (コンタクトシート) で目視確認。

### 6. クレジットを画面下に固定表示するときの可読性

スクロールロールの最中に下部に固定表示するクレジット (金色のローワーサード風) は、背景クリップによって見えたり消えたりする。対処の優先順位:

1. 下部グラデーション (黒→透明、高さ全体の1/3程度) で背景を暗くする
2. それでも白ホリ等の明るい背景では不十分 → 文字に `textShadow: "0 1px 4px rgba(0,0,0,0.6)"` 程度の控えめな影を追加

クレジット行数が多い場合: 部門名+名前2行を上限とし、3行目に溢れる分は2列横並びに変換。1列目と2列目の幅を均等分割してflexで並べる。列数は「名前の最大文字数 × 2 ≤ 表示幅」で確認。

### 4. 点数が少ない枠はループして同じ絵が2回出る

2点の枠にDWELL 2.4秒固定を当てると、10秒の滞在中に p0→p1→p0→p1 と2巡する。「素材が少ない」が「同じ写真の再放送」として画面に出る。上の表のように点数ごとにスケジュールを分ければ起きない。

## ✅ うまく行ったこと

- **選定 → 独立検証 → 切り抜き位置決定 → レンダー実フレーム検証** の4段構え。各段を別エージェントにやらせると、前段の見落としが次段で必ず出てくる。実際、選定20枠のうち9枠が検証段階で修正され、レンダー後の検証ではさらに blocker が6件出た。
- 判断材料を先に機械生成しておく (写真のコンタクトシート、動画の1fpsフレームストリップ、カード切り抜きシミュレータ)。エージェントが「見ずに書く」のを防げる。
- **レンダー結果から枠ごとの表示時刻を計算してフレームを抜く**スクリプト。「意図した素材が意図した位置に出ているか」は、設定ファイルを読むだけでは絶対に分からない。
- 黒落ちのような欠陥は輝度を測れば機械判定できる。目視の前にふるいにかけられる。

### 7. DURATION_IN_FRAMES が小数だとレンダーがクラッシュする

音源の実測秒数 (例: 233.36s) × FPS (30) を直接 DURATION_IN_FRAMES に入れると 7000.8 のような小数になり、Remotionのレンダーが即座にクラッシュする。`Math.round()` で整数に丸めること。

```ts
export const DURATION_IN_FRAMES = Math.round(totalDurationSec * FPS);
```

秒数が決まったらフレーム数を手動で計算してから constants.ts に書くのが安全。

## ❌ 詰まったこと

- 修正が新しい欠陥を生んだ。ループ解消のために入れた「最後の点を保持」が、13枠の黒落ちを作った。**1回直したら必ずもう一度通しで検証する**。
- エージェントの報告は具体的だが、映像の解釈は外すことがある。ある枠の動画を一方は「手を広げて振りを見せる」、もう一方は「受付で指を数える生活シーン」と報告した。**判断が割れたら自分でフレームを抜いて見る**。
- 検証エージェントは「演目と無関係だから差し替えろ」と正論を返してくるが、クライアント側の要望で入っている素材はそれが正解。**確定事項はHANDOVERの「蒸し返さない」欄に理由ごと書いておく**。
- zshで `for pair in "24.6 1-4"` のような複数値ループは単語分割されない。bashスクリプト化するかPythonで書く ([[claude_mistakes]] A-23)。

## 📋 次に同種のエンドロールを作るときのチェックリスト

- [ ] スクロール速度とカード高から「完全表示ゾーン」を計算し、入る点数を決めてから素材を選ぶ
- [ ] 動画は必ずSequenceで包む。包まないと頭出しが効かない
- [ ] 最後の点が動画になる場合、クリップ長を超えて保持されないか確認する
- [ ] 縦素材があるなら object-position を素材ごとに持てる設計にする。横位置素材は元画像クロップで対応
- [ ] 点数ごとに切替スケジュールを分ける (等間隔+ループにしない)
- [ ] 選定と検証は別エージェントに分ける。同じエージェントに検証させても見落としは出てこない
- [ ] レンダー後、枠ごとの表示時刻を計算して実フレームを抜き、もう一度検証する
- [ ] クライアント確定事項は「差し替え禁止」と理由を引き継ぎ文書に書く
