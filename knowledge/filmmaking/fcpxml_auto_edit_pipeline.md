# FCPXML で説明会動画を自動編集する手順 (2026-09-15 ハタチたち5 説明会)

固定カメラ1台で撮った 10:52 の説明会 (FX30 4K 59.94p) と Canva のスライド 21 枚から、Apple 発表会風の編集を FCPXML として生成して Final Cut Pro に読み込んだ。作業一式は `/Volumes/Extreme pro/平成たち祭２/ハタチたち説明会&座談会/_cc_work/` (build_fcpxml.py が生成器、plan_shots.json がショット割り、cuts_final.json がカット、subtitles.json が字幕)。納品は同階層の `_FCP納品/`。

## 流れ

1. 音声を 16k mono に抜いて mlx-whisper large-v3-turbo で単語タイムスタンプ付き文字起こし (10分で31秒)。50ms RMS プロファイルと無音区間も出す
2. カットリストは文字起こしの区切りで下書き → 各 in/out を RMS で「発話の始端-0.12s / 終端+0.18s」に自動で寄せる。噛み・言い直し・「次のページお願いします」・1.3秒超の間を除去。10:52 → 8:39
3. Canva は共有リンクだと MCP の export / copy が権限で拒否される。read-design (テキスト・サムネ) は通る。書き出しは YD の Chrome で共有 > ダウンロード (PNG 全ページ、MP4 全ページを1本)。MP4 は静止ページ 5 秒・動画ページは動画長で並ぶので、PNG との一致でページ境界を割る (似た動画が続くページは目視で境界確定)
4. 動画ページは時間方向の標準偏差で動く領域を検出して切り出し、縦動画はぼかし背景で 16:9 に。ページの冒頭 1.2 秒は Canva の入場アニメなので捨てる
5. 話者の顔トラッキングは YuNet (opencv `FaceDetectorYN`、opencv_zoo の onnx) が Haar より圧倒的に良い (79% 検出)。Haar で穴埋め、外れ値除去、中央値 + Savitzky-Golay で仮想カメラの軌道にする。検出が数秒以上途切れる区間 (話者が画面外や後ろ向き) は寄り/丸窓を使わないショット割りにする
6. 丸窓は ffmpeg の sendcmd で crop の x,y を毎フレーム更新して切り出し、円マスクを alphamerge、1920x1080 の透過 ProRes 4444 に焼く (右下版・左下版の2ファイル)
7. FCPXML を生成 → xmllint で FCP 同梱の DTD (`Final Cut Pro.app/Contents/Frameworks/Interchange.framework/Versions/A/Resources/FCPXMLv1_13.dtd`) に対して検証 → `open -a "Final Cut Pro" x.fcpxml` で読み込み → 再生ヘッドを Control+P + タイムコードで飛ばして screencapture で実画を確認

## うまく行ったこと

- 単語タイムスタンプ + RMS で決めたカット点は、FCP で聴き直さなくても切れ目が自然だった
- スライド全面のときに、動画入りページは PNG ではなく Canva 書き出し MP4 の該当区間を接続すると、ページ内の動画が動いた状態で出せる
- 字幕はベーシックタイトル (`uid=".../Titles.localized/Bumper:Opener.localized/Basic Title.localized/Basic Title.moti"`) に text-style (font="Hiragino Sans" fontFace="W6") を付ける形でそのまま出た。位置は param name="Position" key="9999/999166631/999166633/1/100/101"
- FCP の GUI 操作は System Events (ダイアログのボタン) + Quartz の CGEvent クリック (Terminal が前に出ていると座標クリックが Terminal に当たるので、先に `tell application "Final Cut Pro" to activate`) で回った

## 詰まったこと

- **FCPXML の `adjust-transform position` の単位は px ではない**。FCP 12.3 のインスペクタで実測したところ XML の値 × 10.8 (= 1080/100、プロジェクト高さの 1/100) が px 表示になった。px のつもりで書くと寄りが真っ黒 (画面外) になる
- **`adjust-conform type="none"` で小さい素材を等倍に置くのは効かなかった** (320px の丸窓が画面いっぱいに拡大された)。透過素材はプロジェクトと同じ 1920x1080 で焼いて変形なしで置くのが確実
- **静止画 (`video` 要素) のキーフレームに interp / curve 属性を付けると param ごと無視される** (「キーフレームの補間属性をサポートしていない」)。属性を書かないこと
- **接続クリップの offset は「項目は編集フレームの境界上にありません」の警告が出る**。59.94p 素材を 30p に入れたとき、親の start と子の offset を 1001/60000 でも 2002/60000 でも 100/3000 でも警告は消えなかった。FCP が最寄りフレームに寄せるので実害はない
- **`open -a "Final Cut Pro" x.fcpxml` で FCP を起動すると、読み込み後にメインウインドウが無い状態で止まる**ことがある。その状態で kill すると読み込んだイベントがライブラリに登録されずフォルダだけ残る。先に FCP を普通に起動してライブラリを開いてから XML を open する
- Canva の SIFT 特徴で投影スクリーンの四隅を求めようとしたが、ページごとに結果が 100〜250px ずれた。イベント後にスライドが編集されていて、収録時の投影内容と現行 PNG が一致しないため。スクリーン差し替え自体は、話者がスクリーンの前に立つ時間が 88% だったので見送った
- 自分の tracking の中間結果を CSV に書くとき、クラス名 `st` を AppleScript の変数に使うと予約語で落ちる。細かいがハマる

## 次回同じことをするときのチェックリスト

1. FCP を先に起動してライブラリを開いておく。それから `open` で fcpxml
2. position は px / 10.8 で書く (4K/2160p の場合は px / 21.6)。丸窓などの透過素材はプロジェクト解像度で焼く。キーフレームに interp / curve を付けない
3. 読み込んだら Control+P でタイムコードを打って viewer を screencapture し、寄り・丸窓・字幕・エンドカードの5〜10点を必ず目視する (v1〜v4 は全部これで問題が見つかった)
4. Canva は共有リンクのままでは MCP で書き出せない。Chrome の共有 > ダウンロードで PNG と MP4 を落とす。MP4 のページ境界は PNG 一致で割り、似た動画が並ぶページは export のコンタクトシートで目視
5. 顔トラッキングは YuNet。検出が途切れる区間は寄り/丸窓を計画から外す (ショット割りを track_gaps で自動チェック)
6. 話者がスクリーンの前に立つ収録では、スクリーン差し替えは最初から諦める

## 4K 60p プロジェクトへの対応 (2026-09-15 追記)

元素材が 4K 59.94p の場合はプロジェクト解像度を 3840×2160/59.94p に設定するとクロップロスなし。1080p 版との主な差分:

**Canva スライドの 4K 化**
- PNG の 2 倍拡大はぼける。Canva から PDF を書き出し (`pdf2png4k.py` でラスタライズ) すると文字がベクター品質のまま 4K になる
- Canva の動画書き出しは無料プランで 1080p 止まり (Pro なら 4K 可)。元動画ファイルがあれば差し替えが最善

**PIP (丸窓) の 4K 化**
- 3840×2160 ProRes 4444 を 1 本で焼くと時間がかかる。5 分割した segment ファイルを並列エンコードして ffmpeg concat demuxer で結合する (約 3 倍速)
- セグメント分割数は CPU コア数に合わせて調整。今回は 5 分割

**fcp_probe.sh の crop 座標**
- プロービング用のスクリーンキャプチャの crop 座標は解像度に合わせて変える。4K プロジェクトは 1080p 版の約 2 倍エリアを指定する
- 今回の値: `im.crop((1200,234,3310,1340)).resize((823,432))`

## 追記 (2026-09-15 夜): 4K 59.94p 版に作り替えたときの知見

YD「画質優先、4K60p」で同じ生成器を 3840x2160 / 59.94p に切り替えた (`build_fcpxml_4k.py`)。

- `adjust-transform position` の単位は「プロジェクト高さ / 100」で確定。1080p では 10.8、4K では 21.6 で寄りと丸窓が狙い通りの位置に出た
- **タイトル (ベーシックタイトル) の fontSize と Position は 1920x1080 基準のまま**。4K プロジェクトでも 46pt / Position 0,-400 で 1080p のときと同じ見た目になる。2 倍にしたら字幕が画面をはみ出した
- 接続クリップの `title` に `start` 属性を付けると、親クリップの尺が縮む (S_7 の 12.1 秒が 8.8 秒になった)。title は offset と duration だけにする。読み込み後に FCP から XML を書き出して自分の XML と clip duration を突き合わせると、こういうズレを機械的に見つけられる
- 4K 透過 ProRes 4444 の全編焼きは 10 分素材で 1 時間超かかる (9 fps)。丸窓は使うショットの区間だけ ±0.25 秒で焼く (5 本で 4 分)
- Canva の共有 > ダウンロード > PDF (プリント) は文字がベクターで残るので、PyMuPDF で 3840x2160 にラスタライズすれば 4K のスライドになる。PNG 書き出しは 1920x1080 固定 (Canva 無料)。MP4 書き出しも 1080p まで
- Canva エディタは開いた直後 10〜20 秒スクリプトが走っていて Claude in Chrome の screenshot がタイムアウトする。待ってから操作する
- 59.94p ソースを 59.94p タイムラインに置くときは conform-rate 不要。子要素の offset は親の start と同じ 1001/60000 グリッドで書けば「編集フレームの境界上にありません」警告はほぼ消える (字幕の start を消した後は 0 件)

## 追記 (2026-09-15 夜): 構成変更版で増えた手順と罠

- **音声の整音は RNNoise (`arnndn`) が afftdn より圧倒的に効く**。MKE600 の会場収録で、無音区間 -35 dBFS → -45 dBFS (mix 0.65)、声は -1 dB しか減らない。afftdn は nf/nr をいじっても 1 dB しか下がらなかった。モデルは GregorR/rnnoise-models の sh.rnnn。48kHz mono 前提
- loudnorm を mono 化した信号に掛けると、stereo に戻したとき +3 dB になる (BS.1770 のチャンネル合算)。最終ファイルで測り直すこと
- 字幕は Basic Title ではなく Pillow で透過 PNG (3840x2160) を作って `video` 要素で置く方が、デザイン (ボックス・バー・位置) を完全に制御できる。YD の「スライドに情報があるところは字幕なし」ルールはショット種別 (W/M/V だけ字幕) で実装
- FCPXML の `asset-clip` の子要素は順序が DTD で決まっている: `conform-rate` → `adjust-*` (変形など) → 接続クリップ (`asset-clip` / `video` / `title`)。接続クリップの後に `adjust-transform` を書くと xmllint で落ちる。生成器は先に内在パラメータを出してから子を足す
- Canva ページ内の個々の動画は、書き出し MP4 の時間方向の差分 (動きの割合) でマスクを作り、収縮 (erode) で隣接タイルを分離してから外接矩形を取る。ページの入場アニメ 1.2 秒は捨てる。静止写真タイルは動き 0 なので自動で除外できる
- 動画のベスト区間は Workflow で 1 動画 1 エージェントにコンタクトシート (2fps / 1fps) を読ませて JSON で返させると速い (9 本 2.5 分)。「クリップ末尾は空フレームと天井」「左端に別要素の文字が焼き込まれている」まで拾ってくれた
- 黄かぶり動画のグレーワールド補正は `colorchannelmixer` で bb ≤ 2.0 の制限あり。2 段に分ければ 4 倍まで行けるが、B チャンネルの平均が 6/255 しかない映像 (フィルタで黄色一色) は補正不能。そういう映像は諦めて元のまま使う
- YD が Mac を使っている間は FCP を触らない。代わりに `qc_sheet_v2.py` で plan_shots からフレームを合成して確認する (FCP の見た目とほぼ一致する)

## 追記 (2026-09-16): 構成v3 の監査で見つかった残存不良と、v4 で入れた機械検査

v2 の全面差し戻しを受けて作った v3 にも、同じ種類の不良が残っていた。原因は「整った文字起こし (segment 単位) を信じてカット点を決め、単語タイムスタンプと実音で境界を検証しなかった」こと。v4 で以下を機械検査に落とした。

- **カット境界の単語断片**: `C007_verbatim.json` の単語 (start/end) で各 IN/OUT を挟み、境界をまたぐ単語 (STRADDLE) を全件列挙する (`boundary_check.py`)。v3 では 35 境界のうち 15 か所で「こちら」「そして」「今」「った」「三」「自主練」「その」などの断片が残っていた。判定に迷う境界は 2〜6 秒の短い窓を mlx_whisper (large-v3、verbatim プロンプト) で再文字起こしする (`edge_listen.py`)。**10 秒超の窓は幻覚が出る** (「お楽しみに」「ご視聴ありがとうございました」を捏造した)
- **文字起こしに無い音**: 区間内の 0.8 秒超の無音と、RMS が -22 dB を超えるのに単語が無い区間を列挙する。これで「はい、そして全体」(次の文の言いかけ) と「と思います、思います」(繰り返し) が見つかった。息や語尾の伸びは 0.2 秒以下なので無視してよい
- **言い直しの見落とし**: 「撮影場所は、海老名市立東柏…海老名じゃないかな。海老名市立東柏小学校となっています」のような自己訂正は、segment の文字起こしでは 1 文に整えられて消える。verbatim + 短窓の再文字起こしで初めて出る。**話者が固有名詞を読む区間は必ず短窓で聞き直す**
- **丸窓 (PIP) の偽陽性**: YuNet + Haar + 背景差分の融合トラックは、話者がフレーム外に出ると投影スクリーンの文字や集合写真を「頭」として掴む (v3 の valid 区間の 17% がこれ)。対策: 焼いた丸窓素材そのものを 4 fps でデコードし、YuNet で顔検出 → SFace (`face_recognition_sface_2021dec.onnx`、opencv_zoo) で参照顔 (確実な時刻 24 サンプルの平均) とのコサイン類似度を取り、0.4 以上 + 顔幅 70px 以上 + 顔が円に収まる、を valid とする。話者本人 0.5〜0.85、スクリーン上の他人 0.0〜0.35 で分離できた。19 GB の ProRes を再レンダリングせず、valid マスクだけ差し替えれば済む
- **話者がフレーム外**: この収録では 10:52 のうち約 100 秒、話者が画角の右外にいる (4K 原本で確認)。丸窓は物理的に出せない。次回は撮影時に「話者の動線を画角に入れる」か、2 台目のカメラを話者側に置く
- **同一スライドが続く区間のズーム**: スライドごとに 1.0→1.035 のズームを付けると、同じページ内のカット点でズームがリセットされて「ポン」と跳ねる。連続する同ページ S ショットをグループ化し、グループ全体で 1.0→1.035 になるよう各クリップの開始/終了スケールを配分する (`build_fcpxml_v4.py` の zgroup)
- **ハードカットのクリック**: 主クリップに `adjust-volume amount="0dB"` → `param name="amount"` → `fadeIn`/`fadeOut` (2002/60000s = 2 フレーム) を付ける。DTD 上は `param (fadeIn?, fadeOut?, keyframeAnimation?, param*)`。`adjust-volume` は接続クリップより前に置く (intrinsic-params の順序)
- **無音の借用**: 動画を流す間に話者の声を消したい時は、別の無音区間 (silence_runs から 2.5 秒以上、他の keep と重ならない所) を主クリップとして置く。同じ source 区間を 2 か所で使うと `to_tl` が曖昧になるので、ショットに keep 名を持たせて解決する
- **字幕の折返し**: fugashi の品詞境界だけでは「1,000|円」「と|いう」「して|くれる」「だけじゃ|なくて」「Pop&Lock|パート」が割れる。数字の直後・「と」+「いう」・非自立可能の動詞/形容詞の前・ASCII とカタカナの間、を禁止に追加 (`wrap_ja2.py`)。元の字幕 JSON に手動改行が入っていると、それをそのまま尊重すると単語途中改行が復活するので、手動改行は明示リストの項目だけ許す
- **DTD 検証**: `xmllint --dtdvalid` に FCP 同梱 DTD のフルパスを渡すと "Could not parse DTD" になることがある。DTD を作業ディレクトリにコピーして相対パスで渡すと通る

### 次回チェックリストへの追加

7. 納品前に `boundary_check` (単語断片) と「文字起こしに無い音」の 2 検査を通し、STRADDLE と未説明の音を全部つぶす。固有名詞の区間は短窓で聞き直す
8. 丸窓素材は焼いた後に SFace で「本人の顔が円内にあるか」を全サンプル判定し、valid マスクを作り直す
9. QC シートは同一スライド区間のズーム連続性・丸窓の有無 (フレーム外か) も見る。最後に別エージェントの監査 (4 観点 → 反証) を通してから YD に出す

## 追記 (2026-09-16): FCP 59.94p NDF タイムコード計算式

FCP の viewer キャプチャを「秒 → HHMMSSFF」に変換するとき、`秒 × 59.94` で計算すると 0.1% 遅い位置を指す。先頭で約 0.003 秒、385 秒付近では 0.385 秒のズレになる。

59.94p (60000/1001) の**ノンドロップ TC** は「1 秒ラベルあたり 60 フレームを数える」。正しい変換式:

```python
frame = round(T * 60000 / 1001)
SS = frame // 60
FF = frame % 60
```

`T * 59.94` は 59.94 の丸め誤差を含むため、`60000/1001` を使うこと。FCP の frame grab でフレーム番号を直読みするか、この式で変換してから検証画像を取ると「字幕が消えた後」という誤読を防げる。

発覚の経緯: 2026-09-16 FCP probe エージェントが「TC 42824 (狙い 268.4s) を撮ったら字幕が出ない」と報告。調べると `T × 59.94` で計算した TC が実際の 268.67s フレームを指しており、字幕の終端 268.42s より後だった。`T × 60000/1001` で計算した TC で撮り直すと字幕が正常に映った。

## 追記 (2026-09-16 夜): v5 / v6 で増えた知見

### 丸窓の追跡が外れた区間だけ作り直す

SFace の valid 判定で「顔が円内にない」と出た区間のうち、話者はフレーム内にいるのに追跡が外れているものは、素材を焼き直せば直る。19 GB の ProRes 全体を作り直す必要はない。

手順は、4K 原本に対して区間を指定して YuNet + SFace で追い直し (`track_fix_v6.py`)、得られた中心座標から crop/scale のフィルタ文字列を組み立て (`make_cmd_v6.py`)、元の丸窓と同じレシピで 640x640 の透過 ProRes を焼く (`render_fix_v6.sh`)。出力は `PIP640_fix_<開始秒>.mov` のように区間名で残し、`pip_fix_segments.json` に `src_start` / `src_end` / `file` / `face_ok_frac` を書く。

FCPXML の生成側は、丸窓を置くときにこの区間リストでフレーム単位に切り分け、区間内だけ参照アセットを修正素材に差し替える。修正素材の区間は無条件で valid 扱いにする。ハタチたち5 では 4 区間 (2.0〜5.3 秒) だけ差し替えた。

`face_ok_frac` (再追跡後に顔が円内にあったフレームの割合) を出しておくと、焼き直しても直らなかった区間が分かる。0.5 未満のものは採用しない。

### 丸窓の最小表示時間

valid の連続区間をそのまま丸窓にすると、1 秒未満の塊が点滅して見える。最小 2.0 秒、1 秒以内のギャップは結合、で落ち着いた。結合してから最小長で足切りする順番にしないと、細切れが全部消える。

### 丸窓がスライドの中身を隠すとき

スライドによっては右下に文字の箱があって、既定位置の丸窓が隠す。全体の位置を変えると他のスライドで不自然になるので、ショット単位で直径と中心を上書きできるようにしておく。ハタチたち5 では 1 ショットだけ 600px → 384px に縮めて右下隅 (中心 3620, 1950) に寄せた。生成器側は `{(src_in, src_out): (cx, cy, diameter)}` の辞書で持たせた。

### 境界の確認は 10ms RMS で見る

単語タイムスタンプと再文字起こしで境界を決めた後、その前後 ±0.3 秒の RMS を 10ms 刻みで並べて見る。50ms 刻みだと「子音の立ち上がりの直前」と「母音の途中」が同じ値に見えてしまい、単語の頭を削っているのに気づかない。カット直前が -35 dB 前後で平らなら安全、-20 dB より大きい値が並んでいたら発声の途中。

区間の内側も見る。0.8 秒を超える無音で、RMS が -35 dB を上回るフレームの割合が半分以上あるところは、文字起こしに乗っていない発話が入っている。

### W (ワイド撮影映像) ショットは話者がフレーム内か確認する

固定カメラだと話者が画角の外に歩いて出る。W ショットを置く前に、その区間の頭・中間・尻の 3 フレームを原本から抜いて、話者が写っているか目で見る。ffmpeg で `-ss <秒> -i <原本> -frames:v 1` を 3 回叩くだけでいい。トラックの valid フラグは丸窓用の判定 (顔が円内か) なので、W ショットの可否には使えない。

### 動画タイルの切り出しは隣接要素の写り込みを見る

Canva ページから動画の領域だけを切り出すとき、指定した矩形の端に隣の要素が数十 px 入り込んでいることがある。切り出した直後の 1 フレームを原寸で見る。ハタチたち5 では p15 の左タイルで右側に別の要素が写り込んでいて、v6 で切り出し直した。

人が横切る、カメラが動く、といった理由で使えない区間もある。タイルを 0.25 秒刻みのコンタクトシートにして、使う区間を決めてから切り出す。

### 生成後の構造チェックを別スクリプトにする

DTD 検証は XML として正しいことしか言わない。生成器とは別に検査スクリプトを置いて、リソースの media-rep が実在するか、シーケンス長とスパインの合計が一致するか、丸窓の連続長が最小値を下回っていないか、位置とスケールが意図どおりか、主クリップ全部にフェードが付いているか、同一ページのズームが前のショットの終値から始まっているか、を毎回出す。生成器を直したときに壊れた場所がすぐ分かる。

### タイムライン基準の SRT

YouTube 用の全文字幕は、source 秒の字幕リストを keep 区間でタイムライン時間に写像して作る。keep の外に出た部分は捨て、複数の keep にまたがる字幕はタイムライン上で連続する部分だけ結合する。写像した結果 1 秒未満になった断片は捨てる。フレーム単位 (round(T × 60000/1001)) で計算しないと、映像とじわじわずれる。
