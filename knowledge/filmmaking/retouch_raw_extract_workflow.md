# レタッチ希望写真 → RAW自動抽出ワークフロー

## 概要

クライアントがLINEアルバム等で送ってきた「レタッチ希望」スクショ(ファイル名が化けて元名不明)を、元RAW(.CR3等)に突合して別フォルダに抽出する手順。2026-07-01 つん案件で確立。

## 詳細

### 典型フォルダ構成(例: つん)
- `レタッチ希望写真/` : クライアントの希望スクショ (`LINE_ALBUM_*.png`)
- `RAW/` : 全カットRAW (`つん-XXX.CR3`)
- `JPEG/` : 全カットJPEG (`つん-XXX.JPG`、RAWと同名同番)

### 核心ロジック(ここが肝)
LINEアルバムのスクショは名前が `LINE_ALBUM_..._1〜N.png` に化けており **元ファイル名の情報がゼロ** → 名前では突合不可。
代わりにスクショ上部タイトルバーの **「(現在位置 / 総数)」カウンター** を使う。

1. 各スクショの `(X / 総数)` を読む(OCR or 目視)。総数がRAW枚数と一致するか確認(=全カットアルバムの証拠)。
2. **アルバムの並び順を特定**する。つん案件は「新しい順(逆時系列)」だった。
   - JPEGのEXIF DateTimeOriginalで時系列ソート → ファイル連番と一致するか確認。
   - 特徴的で一意に見分けられるカット1枚を画像内容で突合(アンカー)し、そのカウンターと突き合わせて式を導く。
   - つんの式: **元番号 = (最終番号+1) − カウンター**  (総数264, 番号094〜357 → `358 − X`)
3. 全スクショに式を適用して番号を確定。
4. **必ず目視で1対1照合**(連写でポーズ酷似のコマがあるため、知覚ハッシュ単独を信用しない。カウンターが最も確実)。
5. 確定RAWを別フォルダに **コピー**(移動でなく)。`対応表.csv` と `確認シート.pdf` も出力。

---

## ✅ うまく行ったこと

- カウンター `(X/264)` が最強の手掛かり。連写で見分け不能なコマもこれで一意確定。
- 並び順は「アンカー1枚を内容照合 → 式を逆算」で特定。今回は逆時系列で `358−X`。
- EXIF orientation=8(縦位置)を考慮し、表示向きを揃えてから照合。
- コピー運用で元RAWフォルダ無傷。確認シートPDFでクライアント確認も一発。

## ❌ 詰まったこと

- 最初「アルバム順 = ファイル名順」と誤認 → 実際は逆時系列でズレる。**並び順は必ずアンカーで検証**すること。
- 知覚ハッシュ(phash/dhash)だけだと連写で誤コマを掴む(距離が近すぎる)。ハッシュは "候補出し" 止まり。
- スクショの白背景と LINE ビューアの黒レターボックスで自動クロップが不安定 → カウンター方式に切替が正解。
- OCRは桁落ちする(75→5, 230→220)。最終はタイトルバー画像を目視で読むのが確実。

## 📋 次回同じことをするときのチェックリスト

- [ ] レタッチ希望フォルダの中身がスクショか元画像か確認(元名が生きてれば名前で一発)
- [ ] スクショなら `(X/総数)` を全枚数読む(桁落ち注意、最後は目視)
- [ ] 総数 == RAW枚数 を確認
- [ ] EXIFで時系列ソートし、アンカー1枚で並び順の式を確定
- [ ] 式を全枚数に適用 → 目視で1対1照合(連写に注意)
- [ ] RAWは「コピー」で別フォルダへ。`対応表.csv` + `確認シート.pdf` 出力
- [ ] これだけは絶対: **並び順をアンカー検証するまでコピーしない**
