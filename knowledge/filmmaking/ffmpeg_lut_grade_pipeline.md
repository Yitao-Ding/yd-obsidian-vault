# ffmpeg 3D LUT カラーグレード パイプライン

対象: FX30 4K Mov 素材を ffmpeg で 3D LUT グレードしながら H.264 書き出しする場合。

## LUT パラメータ (プペル number/琴 2026-09-04)

```
sh07_hi13_sat12.cube (65^3 点)
シャドウ  0.25 → ×0.7  (0.175)
中間      0.50 → 固定   (0.500)
ハイライト 0.75 → ×1.3  (0.975)
白        1.00 → 固定   (1.000)
彩度補正  ×1.2 + ガマット圧縮
```

LUT は `プペル/number/_grade/sh07_hi13_sat12.cube` に保存済み。他の演目にそのまま使えるが、音声オフセットは曲ごとに測り直しが必要。

## 彩度調整とガマット圧縮

単純に彩度を掛けると飽和クリップが発生する。

- 素材 (before): 青 9.6% 飽和、赤 2.1% 飽和
- 単純 ×1.2: 飽和ピクセルが増大 (塗り絵状態)
- ガマット圧縮後: 0.02% (元の 0.23% より改善)

**方法**: 輝度 (Y) を保ちながら彩度を圧縮する。Rec.709 輝度係数を使って Y = 0.2126R + 0.7152G + 0.0722B を計算し、飽和域では (pixel - Y) * scale + Y で引き戻す。PCHIP 補間で C¹ 連続にすると折れ点の LUT 補間誤差 (最大 7 コード) を解消できる。

```python
from scipy.interpolate import PchipInterpolator
import numpy as np

xs = np.array([0.0, 0.25, 0.50, 0.75, 1.0])
ys = np.array([0.0, 0.175, 0.50, 0.975, 1.0])  # tone curve
tone = PchipInterpolator(xs, ys)

# LUT グリッド生成 → .cube に書き出す
N = 65
lin = np.linspace(0, 1, N)
```

## アップスケーラ選択

4K Mov をサムネイル比較した結果: lanczos > spline > bicubic (subjective)。標準コンテンツでは差は微小だが lanczos を選択。

## ffmpeg 書き出しコマンド骨格

```bash
ffmpeg -y -i "$MOV" \
  -f lavfi -t "$DUR" -i "aevalsrc=0:c=stereo:s=48000" \
  -i "$FX30_WAV_RESAMPLED" \
  -filter_complex "
    [0:v]fps=30,format=gbrp10le,
    lut3d=file=$LUT,
    scale=3840:2160:flags=lanczos,
    format=yuv420p[v];
    [2:a]volume=1.0[a]
  " \
  -map "[v]" -map "[a]" \
  -c:v libx264 -profile:v high -level 5.1 -crf 18 \
  -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
  -c:a aac -b:a 192k \
  out.mp4
```

VFR (24p+30p 混在) 素材は `fps=30` で CFR に変換してから LUT を掛ける。

## 色精度の検証

同一フレームを pipeline 前後で比較:
- パイプライン → 1080p RGB → 比較
- 平均誤差 0.65 コード、CRF 18/20 で変化なし → 許容

## AAC ピーク検証の落とし穴

音声クリップ確認でモノラルダウンミックスすると **位相加算で +3dB** になり、false positive が出る。

- モノラルで計測: ピーク +1.5dBFS → 一見クリップ
- ステレオで計測: ピーク 0.846 = -1.4dBFS → 問題なし
- AAC 透過性誤差: -50.6dB (ほぼ透明)

**ピーク検証は必ずステレオで行うこと。**

161 MB (4.85 Mbps) は元が 1080p 4Mbps のアップスケールのため低い。隣の定点 380 MB (11.4 Mbps) と揃えるなら CRF を下げて焼き直しが必要。

## ルック方針の注意

`色合わせ手順.html` は「iPhone の潰れた黒を FX30 に寄せる (ブラックリフト)」方針。sh07 LUT はシャドウ ×0.7 で逆方向に沈める。FX30 定点と並べる前提なら方針が衝突する — 単体のルックとしてのみ使う。

---

✅ うまく行ったこと
- PCHIP 補間で C¹ 連続な LUT を生成し、補間誤差を 7 コード→許容範囲に抑えた
- ガマット圧縮で元素材より飽和が少ない結果 (0.23%→0.02%)
- 色精度検証 (平均 0.65 コード) でパイプラインの再現性を確認

❌ 詰まったこと
- モノラルダウンミックスで AAC ピークが +1.5dBFS と出て一瞬クリップと誤認。ステレオで測り直して解消
- 中間調が持ち上がりすぎ・白が 249 に落ちる問題 → PCHIP の制御点を調整 (白 1.0 固定を明示)
- CRF 20 の時点でビットレートが 3.1 Mbps と低く、暗部バンディングを懸念。CRF 18 に上げて確認

📋 次回同じことをするときのチェックリスト
1. LUT 生成: 白点 (1.0) を制御点に含めないと 249 に落ちる
2. 彩度調整: 先に素材の飽和率を計測 → 閾値超えならガマット圧縮必須
3. ピーク確認: 必ずステレオで計測
4. VFR 素材: `fps=N` でまず CFR に変換してから処理
5. 出力サイズが低い場合: 元素材のビットレートを確認して期待値を調整
6. 他の定点と並べる場合: カラー方針 (リフト vs ドロップ) を事前に統一
