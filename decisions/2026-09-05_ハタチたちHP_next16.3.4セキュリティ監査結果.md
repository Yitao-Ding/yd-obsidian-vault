# ハタチたちHP — next@16.3.4 セキュリティ監査結果

## 状況

pnpm audit + GitHub Security Advisories API による4観点監査ワークフロー (24エージェント) を 2026-09-05 実行。うち13エージェントが完了、11エージェントがセッション上限でタイムアウト。dependencies / next.js の観点のみ完結した結果を記録する。

## 主要所見

### 脆弱性まとめ

- **pnpm audit --prod: 14件** (next 9件 + next経由 postcss 8.4.31 が4件 + next経由 sharp 0.34.5 が1件)
- **pnpm audit未掲載のcritical 2件**: GHSA-2xp9-vwfh-vxw4 (AVIF RCE) / GHSA-p293-qw3h-jr36 (Windows RCE) — どちらも next < 16.3.3 が対象、2026-08-25 公開

### 実際の危険度: 低

このサイトには攻撃成立の前提条件がすべて存在しない:
- Server Actions なし → GHSA-m99w / GHSA-89xv / GHSA-4c39 / GHSA-955p 不成立
- middleware/proxy なし → GHSA-6gpp 不成立
- rewrites/redirects なし → GHSA-p9j2 不成立
- `/_next/image` は Vercel edge が 400 INVALID_IMAGE_OPTIMIZE_REQUEST を返し、Next の optimizer/sharp が動かない → AVIF RCE 不成立
- Vercel は Linux (iad1) → Windows RCE 不成立
- postcss はビルド時に自前 CSS を処理するだけ → 攻撃者制御のCSSが通らない

現時点での実害リスクはゼロ。**ただし応募フォーム等で Server Actions を追加した瞬間に複数件が実害化する**。

### 推奨対応: next@16.3.4 へアップグレード

```bash
cd "/Users/ittou/AI projects/hatachi-tachi-website"
git checkout -b chore/next-16.3.4
pnpm add --save-exact next@16.3.4 react@19.2.8 react-dom@19.2.8
pnpm add --save-exact -D eslint-config-next@16.3.4
pnpm audit --prod                 # 期待: 0件
pnpm lint && pnpm build           # 全ルートが prerender のまま出ること
pnpm dev                          # / / /news / /news/<slug> を目視
git add package.json pnpm-lock.yaml
git commit -m "next 16.3.4 / react 19.2.8 に更新 (セキュリティ修正)"
git push -u origin chore/next-16.3.4
# Vercel Preview URL を確認後、main にマージ (push は YD 確認後)
```

**破壊リスクは低い**: 16.2.6 → 16.3.4 はマイナー。Breaking Changes 節なし。このサイトが使う面 (next/image カスタムローダー、next/font/google、robots.ts/sitemap.ts、revalidate=3600、generateStaticParams、force-dynamic) に関わる変更はすべて additive か修正のみ。
