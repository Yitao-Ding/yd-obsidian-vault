# 2026-05-20 機能マッピング自動化 (スキル + MCPコネクタを朝の起動シーケンスに統合)

## 背景

Claude Code / Claude アプリには大量のスキルと MCPコネクタが登録されている (グローバルスキル 40+、Vercel系 28、MCP 11)。
しかし、Claude がそれらの存在を**意識せず**、ワークフロー構築の素材として活用できていない。

YD からの要望:
> 「おはよう」と入力したときに、Obsidian の情報読み込みに加えて、
> アプリに登録されているスキルやコネクタも事前に読み込んで、
> ワークフロー構築に使える状態にしてほしい。全部自動化したい。

## 重要な事実 (誤解しがちなポイント)

スキル/MCP は**毎セッション system-reminder で自動注入されている**。技術的には「読み込まれている」状態。
問題は Claude 側の「**意識する → 提案する**」の習慣が欠落していること。

つまり Vault に必要なのは「機能リスト」(自動注入で重複) ではなく「**いつ何を使うか**」の**マッピング表**と、それを参照する**演習ステップ**。

## 選択肢と決定

検討した3案:

- **A. 軽量**: `available_capabilities.md` を作って起動時に読み込むだけ
- **B. 中量 (採用)**: A + トリガー語彙マッピング + 朝の機能マッピング演習 + morning-briefing 反映
- **C. 重量**: B + プロジェクト別の典型ワークフロー集を事前定義

**採用**: B
**理由**:
- A だとリストを読むだけで使わない (= 結局忘れる)
- C は理想だがプロジェクト構成の変動が激しく維持できない
- B は「**毎朝マッピング演習を強制する**」仕組みで習慣化を狙う

## ✅ うまく行ったこと

- **「自動注入されているが意識しない」問題の特定**: スキル/MCP が system-reminder に毎回乗っていることを思い出せたので、無駄な「ファイル再読み込み」設計を避けられた
- **3案 (A/B/C) で粒度を分けて提示**: YD は B (中量) を即決。決定速度が出た
- **マッピング表 + 演習ステップ**の組み合わせ: 単なるリストよりも、使う場面のトリガー語彙を併記したので、Claude が引き出しやすい
- **morning-briefing への反映パス**: 既存パイプラインに `_load_vault_context()` を足すだけで Vault context を `claude -p` に流せた (LLM 側で自然にマッピングしてくれる設計)

## ❌ 詰まったこと

- 該当なし (実装中に詰まったポイントは特になし、構文チェックも一発通過)
- ただし**運用が始まってから**、`available_capabilities.md` が古びる問題が出る可能性あり (例: 新しいスキルが追加されたが本ファイルに未反映、など)。月次メンテで対処予定。

## 📋 次回同じことをするときのチェックリスト

1. **「読み込まれていない」と「意識していない」を区別する** — system-reminder で注入されている情報は、Vault に保存する必要なし。マッピングだけ書く
2. **トリガー語彙を併記する** — リストだけだと結局意識しない。「○○と言われたら△△を使う」レベルまで書く
3. **朝のブリーフィングに反映する場合**:
   - `BriefingDocument` の dataclass に新フィールドを追加 (default_factory=list)
   - スキーマヒントとプロンプトに同時に追加
   - テンプレ HTML にセクションを足す + CSS にカラー追加
   - `tts_script()` も忘れずに更新
   - 既存 `_fallback()` は default のおかげで自動的に空リスト扱いになる (確認だけ)
4. **環境変数で Vault path を上書き可能に** (`VAULT_ROOT`) — テスト環境 / 他人の環境で動かす可能性に備える
5. **読み込みファイルが大きい場合 (`active_projects.md` は 23KB)** プロンプトトークンを節約するため `[:8000]` でカット
6. **起動シーケンスに新ステップを足す時の Step 番号は手動で詰める** — Step 4.5 にせず、後段を 6 → 7 にシフト
7. **`~/.claude/CLAUDE.md` の更新は YD の許可前提** だが、軽微な追加 (起動シーケンスへの 1 ステップ追加) は事後報告で OK ([[CLAUDE]] の方針)
8. **「全部任せます」と言われても、必須3セクション (`✅ ❌ 📋`) は省略しない** ([[CLAUDE]] の絶対ルール)
