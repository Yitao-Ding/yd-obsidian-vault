# 9月フィリピン渡航の日程表を Notion データベースで作成

## 状況

YD からカレンダーのスクリーンショット (9/20-10/3) を受け取り、「場所ごとに、いつ行くのか・どういう場所なのか・何をするのか・街の特徴・事前に知っておくこと・参考記事・写真を、一目で分かるデータベースにしてほしい。カレンダー形式ではなく Excel のような表で、写真はギャラリー表示」という依頼。置き場所は Notion「Grow me:) 9月フィリピン計画」ページの先頭。

## 選択肢と選んだもの

カレンダービューではなくテーブル + ギャラリーの2ビュー構成にした。カレンダーは「いつ」しか答えないが、YD が知りたいのは「どういう場所か」まで含むため、1行1訪問先のデータベースが合う。

プロパティは 予定 / 日付 / 時間帯 / 都市 / 種別 / 概要 / やること / 事前メモ / 参考リンク / 確度 の10個。カレンダーに時刻が入っていないので、時間帯は 午前・午後・夜・終日・未定 の選択肢にして、分からないものは全部「未定」にした。読み取れなかった予定名は「確度: 要確認」で明示し、推測で埋めない方針にした。

写真は Wikimedia が取得できなかったため Unsplash の外部URLをページカバーに設定。ギャラリービューはページカバーを表示する既定設定で作った。

## ❌ 詰まったこと

## 📋 次回同じことをするときのチェックリスト

1. 予定の正体を調べる前に、その案件の Notion To do データベースの各ページを全件読む。Web検索より先。ほぼここに答えがある
2. カレンダーのスクショを渡されたら、まず Google Calendar コネクタで同じ期間を引いて突き合わせる。一致しなければ別アカウントのカレンダーなので、そこで打ち止めと判断する
3. 写真は施設・団体の公式サイトを WebFetch して画像の直URLを抜くのが一番早い。ホテル公式、NGO公式、政府観光省はだいたい素の img タグで出る。Wikimedia (upload.wikimedia.org / commons / REST API) は WebFetch が cache-only で全滅なので当てにしない。埋まらないところだけ unsplash.com/s/photos/<キーワード> を WebFetch して直URLを取り、?w=1600&q=80 を付ける。Flickr は「All rights reserved」が多いので使わない
4. Notion でインラインDBをページ先頭に置くには、create_database (末尾に付く) → fetch でページ本文の database タグを取得 → replace_content で順序を入れ替える。全部のタグを新しい本文に含めれば消えない
5. ギャラリーのカードプレビューは API から「ページカバー」に指定できない。DSL の COVER はプロパティ名しか受けず、`COVER "Page cover"` は validation_error になる。確実に画像を出すには、ページカバーを設定したうえで本文の先頭にも同じ画像ブロックを入れる。どちらのプレビュー設定でも絵が出る
6. 読み取れない項目は推測で埋めず「確度: 要確認」の選択肢を作って明示する。後から本人に5件だけ聞けば済む形にする
7. 地域別ページは別DBを作らず、create_view に parent_page_id を渡してリンクドビューを置く。FILTER "都市" = "マニラ" のように絞るだけで、正本は1つのまま。このとき「移動」のような中間値を都市に残すとどのビューにも出てこない行ができるので、行き先の都市に寄せる
8. 本文に [[ ]] 形式の Wiki リンクを書くと Notion では `\[\[...\]\]` とエスケープされて出る。Notion 側では使わない
