# Vault 完全自動保存を全経路 (Claude Code / チャット / Cowork / iPhone) に導入

YD 指示 (2026-08-24 Cowork): 「俺のも完全全自動で保存するようにしてほしい。チャットも Code も Cowork も全部。iPhone でやったやつも全部」。彼女用の Notion 版第二の脳キットを作った流れで、自分の Vault も「保存して」と言う場面をゼロにする。

## 選択肢と決めた理由

Claude Code は、モデルの善意に頼る Phase 3 (セッション終了時に自分で保存) だけでは、終了せず放置したセッションやクラッシュで漏れる。transcript は `~/.claude/projects/` に全部残っているので、それを機械的に読んで `claude -p` (Sonnet) に振り分けさせる方式にした。SessionEnd フック (即時) と launchd 30分毎 (取りこぼし回収) の二重。抽出モデルは Sonnet (1回30秒前後、Max 20x の枠を圧迫しない。YD 選択)。会話の生ログも raw/chats/claude_code/ に残す (YD 選択、git 対象外)。

iPhone のチャットは Mac に届かないので、GitHub コネクタで Vault リポの inbox/ に新規ファイルを置き、Mac 側が pull して振り分ける方式にした (YD 承認)。Notion 化は YD の Markdown 方針に反するので却下。Cowork は Mac アプリ起動中ならブリッジで直接書けるので、書けない時だけ GitHub 経路に落ちる。

同期は 10分毎の launchd。rebase ではなく merge にし、append-only ファイルは merge=union にした。

## 実装

- `~/.claude/vault-autosave/vault_autosave.py` (watch / session / inbox)、`vault_sync.sh`、`hook_sessionend.sh`
- `~/Library/LaunchAgents/com.yd.vault-autosave.watch.plist` (1800秒)、`com.yd.vault-autosave.sync.plist` (600秒)
- `~/.claude/settings.json` hooks.SessionEnd 追加 (バックアップ: settings.json.bak-20260824-*)
- Vault: `inbox/README.md`、`.gitattributes` (merge=union)、`.gitignore` に raw/chats/claude_code/、`00_CLAUDE_BOOT.md` 末尾に自動保存の節、[[vault_autosave]] (運用マニュアル)
- Preferences / Cowork 全体指示の新文面は YD が貼る (アプリ設定)。GitHub コネクタの接続も YD 作業

## ✅ うまく行ったこと

- 初回テストで Sonnet が「2026-08-05『企業就職しない』決定 vs 8/24 マイナビ6社エントリー」の矛盾を検出し、identity を書き換えずに open_questions へ提案として書いた
- 2本目のセッションでは「全件セッション中に完了済」と判断して log.md 1行で済ませた。会話中の 📥 報告を見て重複を避けるルールが効いた
- 既存の launchd パターン (ai-researcher 等) と同型なので、YD の運用感覚と揃う

## ❌ 詰まったこと

- remote が 2026-08-11〜15 の MacBook Neo 側 commit で16件先行しており、この MacBook Pro 側は 08-11 以降 push していなかった (Neo 移行時に「故障・ロスト」と記録されたが実機は稼働中)。log.md と mistakes/tool_usage_mistakes.md が衝突 → union で手動マージして push。remote の identity/profile.md は「機体は Neo、ittou パスは消失」と書いてあり、現状と食い違う (YD 確認待ち)
- `git pull --rebase` はマージコミットを含む履歴と相性が悪く再衝突した → merge 方式に変更
- macOS に flock コマンドが無い → mkdir ロック

## 📋 次回同じことをするときのチェックリスト

1. 無人ジョブの `claude -p` は、起動シーケンス省略・質問禁止・迷ったら保存しない・identity は提案止まり、をプロンプト冒頭に書く
2. フック内で `claude -p` を呼ぶなら環境変数で再帰を止め、ジョブ自身の transcript をマーカーで除外する
3. 同期は merge + `.gitattributes merge=union`。rebase は使わない
4. 別 Mac の存在を疑ったら `git log main..origin/main` と remote の decisions を先に読む
5. 動作確認は `launchctl list | grep vault-autosave` と logs/autosave.log の rc=0

## 追記 (2026-08-24 13:40): iPhone 経路を GitHub から Google Drive に変更

YD「GitHub 元々繋がってる」を受けて確認したところ、claude.ai のコネクタ一覧に GitHub は無く (ListConnectors / レジストリ検索とも該当なし)、GitHub の remote MCP は claude.ai のカスタムコネクタでは認証できない (GitHub 公式の install-claude.md に明記)。つながっているのは Claude Code / Projects 用の GitHub 連携で、チャットからファイルを書くツールは持たない。

代わりに Google Drive を採用。Google Drive コネクタは接続済みで iPhone でも使え、Mac には Google Drive デスクトップ (save.yitao@gmail.com) が同期している。Drive の `ObsidianVault-inbox` フォルダに置いた Markdown を watch が取り込む。読み取りは同フォルダ `_boot/` の写し。テスト: Cowork から Drive にファイル作成 → 1分で Mac に同期 → inbox 取り込み → Sonnet が knowledge/programming/tools/vault_autosave.md を訂正して log.md に記録、まで2分で完走。

教訓: 「つながっている」の中身 (統合 / コネクタ / CLI 認証) を ListConnectors で実測してから経路を設計する。
