# 2026-07-02 LiteOP 品質スイープ13件修正 + Fable設計/Sonnet実装の分業体制

> JAMBOREE STUDIO BATTLE Lite OP動画(¥70,000・5000人会場)の「雑なところ全部直して」フェーズ。
> 正本の技術詳細は `/Users/ittou/整理済み/Lite_イベントOP_2024-2026/HANDOVER_映像制作.md` §7c 0-a〜0-c。

## 状況
- YD指示①「ロゴの白背景をきれいに抜いて、欠けを防いで」②「雑なところを全部チェックして直して」③(iPhone実機レビュー後)「顔が白飛び/アニメ単調/チームロゴ読めない/ラストのだるま小さい」
- Fable 5のセッション上限に途中で当たったため、**YD指示で「Fable=設計・オーケストレーション、Sonnet=実装・検証」の分業に切替**

## 決定・実施内容
1. **ロゴ透過**: `qlmanage→ffmpeg colorkey=white` を廃止、**`pdftocairo -png -transp -r 600`** に切替(.aiはPDF互換・白背景オブジェクト無しなので真の透過が取れる)
2. **品質スイープ手順**: 全編を0.5s刻み200フレーム展開 → Workflowで9視点並列レビュー(時間帯8+ラベル精査1) → トリアージ(52→18) → Sonnet検証4体が**ピクセル実測**(輝度・座標・角度) → 確定のみ修正
3. **修正13件 / 実測棄却4件**(B3収束点ズレ・だるま目の左右・名前角度・52s断片は「問題なし」を数値で実証)
4. **YD実機FB**: 顔=Tintマップ先の輝度上限で制御(B&Cはハイライト保護で効かない)、FX増量、B11は巨大だるま降臨→震え縮小→地響きドーン→開眼(瞳入れ)に再構築

## ✅ うまく行ったこと
- **分業プロトコル**: 実装指示を「変更前→変更後のコード断片+ES3制約明記+挿入アンカー指定」で渡すと、Sonnet実装の事故ゼロ(9ラウンド連続)。検証も「計測タスク+報告フォーマット指定」で定量報告が返る
- **実測ベースの棄却**: レビューエージェントの指摘の約1/3は誤検出。修正前にSonnetにピクセル計測させることで、無駄な修正と改悪を回避できた(例: ビーム収束は1.2px以内で完全一致していた)
- **「見えない光より入る瞳」**: 白飛びした顔に白い光は見えない→暗い瞳を描く発想転換で、だるまの目入れの意味も完成
- 修正→1フレームレンダー→数値検証(白飛び%・画素値)のループが高速(1周3〜5分)

## ❌ 詰まったこと
- **CAMERA_SHAKEの常時108%スケール**: ビネットの上に移動したレイヤーだけスケールされず座標がズレる(瞳が頬に着地)。`CX+(x-CX)*1.08` の事前補正で解決
- **GLOBAL_GLOWのブルームが小さな暗い要素を洗い流す**: 白い顔の上のr13黒ディスクが170-200/255まで明るくなる。グロー調整レイヤーの上に出して解決
- **新型Brightness&Contrastのハイライト保護**: bri=-60でも白飛びがほぼ変わらない。輝度制御はTintマップ先色を暗くするのが唯一効くレバー(§7b既知事項の再確認)
- Fableサブエージェント18体が一斉にセッション上限で全滅(Workflowの検証フェーズ)。以後サブエージェントは model:sonnet 指定で回避

## 📋 次回同じことをするときのチェックリスト
1. レビュー指摘は**修正前に実測検証** — 座標・輝度・角度をPILで数値化してから直す(誤検出1/3)
2. 実装をサブエージェントに任せる時: 変更前後のコード断片・ES3等の環境制約・挿入位置アンカーを明記、「リファクタ禁止」と書く
3. AEで暗い要素が明るく写る→GLOBAL_GLOWの位置関係を疑う / 白飛びが暗くならない→B&CでなくTintマップ先を触る
4. 調整レイヤー(シェイク等)の上下でレイヤーを移動したら**座標系が変わっていないか1フレーム確認**
5. Fableの枠切れに備え、大量並列はSonnet指定を最初から検討(検証・実装はSonnetで十分な精度だった)
