# 2026-05-21: Claude Code エージェントチーム機能の有効化

## 状況

YD が Claude Code の公式ドキュメント「エージェントチームの調整」記事 (https://docs.claude.com/ja/agent-teams) を共有して、「これらの記事を参照してサブエージェントを使えるようにしてください」と依頼。

ドキュメント要旨:
- **エージェントチーム** = Claude Code v2.1.32+ の**実験的機能**。複数の Claude Code インスタンスがチームとして連携。1セッションがリーダーになり、メンバーは独立 Claude インスタンス。
- メンバー間は直接メッセージ送受信可、共有タスクリストで自己調整。
- 既存の **subagents** (メインに結果だけ返す軽量委任) とは別物。
- 表示モードは **in-process** (Shift+Down でメンバー切替) と **分割ペイン** (tmux / iTerm2+it2 必要) の 2種。
- デフォルトでは無効、`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` で有効化。

現セッション開始時の環境:
- Claude Code 2.1.146 (v2.1.32+ 要件 OK)
- tmux: 未インストール
- iTerm2 + it2 CLI: 未インストール
- `~/.claude/settings.json` に `env` セクション無し

## 選択肢と決定

| 選択肢 | メリット | 不採用理由 |
|--------|---------|----------|
| A. グローバル `~/.claude/settings.json` に env 追加 + tmux インストール | 全プロジェクトで有効、`teammateMode: "auto"` で tmux 内なら自動で分割ペイン、外なら in-process。シンプル | 採用 |
| B. プロジェクト単位 (`<proj>/.claude/settings.json`) で有効化 | 影響範囲を絞れる | エージェントチームは横断的に使う想定なのでグローバル一択。プロジェクト単位は逆に管理コスト高 |
| C. env だけ追加、tmux は入れない | 即動く (in-process モード) | 分割ペインの「全メンバーの動きを同時に見渡せる」体験こそが価値、後で必ず入れることになるので先に入れた |
| D. iTerm2 + it2 + Python API 構成 | macOS でリッチな統合 | tmux の方が枯れていて、`tmux -CC` で iTerm2 と統合もできる。複雑度を下げた |

**決定: A**。理由:
- グローバル env は他の env を持っていなかったので影響範囲が明確 ([[available_capabilities]] にも書いてある「YD は env 設定持ってない」状態)
- tmux はインストールサイズ小、依存少、今後 [[parallel_claude]] や他並列系でも使い回し可能
- `teammateMode` は明示せず `"auto"` デフォルト (= tmux 内なら分割ペイン、外なら in-process) で自然な挙動

## 実装内容

### 1. settings.json 編集

`~/.claude/settings.json` の `permissions` 直後に env セクション追加:

```json
{
  ...
  "permissions": {
    ...
    "defaultMode": "acceptEdits"
  },
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  },
  "model": "opus[1m]",
  ...
}
```

### 2. tmux インストール

```bash
brew install tmux
# → tmux 3.6b @ /opt/homebrew/bin/tmux
```

### 3. 有効化の動作確認

予想外に**現セッション内で deferred tools が即座に注入された**: `TeamCreate`, `SendMessage`, `TeamDelete` が `<system-reminder>` 経由で利用可能になった。settings.json 編集後に Claude Code を再起動しなくても認識される模様 (本来は再起動推奨だが、現セッションでも動く)。

YD が別ターミナルで以下を実行:


## ✅ うまく行ったこと

- **バージョン要件の事前確認が機能**: `claude --version` で 2.1.146 を即確認、v2.1.32+ クリアを最初に押さえた。これがダメだと全部やり直しだった。
- **YD の好み「小さく始めて回す」と整合**: tmux インストールも含めて 5分以内に有効化完了。重い意思決定はなし。
- **既存リソースの活用**: parallel-claude が 2026-05-20 に生成した Arte Grow リサーチ第1版 (24.5KB) を **試走の入力** として使い回せる → 0 ベースで始めるより遥かに深い議論ができる構成に。
- **deferred tools の即時利用**: 設定編集後に再起動なしで現セッションでも `TeamCreate` などが利用可能になった (想定外の朗報)。

## ❌ 詰まったこと

- **「サブエージェント」用語の混同**: YD が共有した記事はエージェントチーム機能 (実験的) の話だが、本文中に「subagents」(既存の軽量委任機能) の比較が出てくる。Claude Code には「サブエージェント」と訳される概念が **2つある**ことを最初に整理しないと、YD が「サブエージェント」と言ったときどちらを指すか分からなくなる。今回は記事の主題から「エージェントチーム機能」と判断したが、念のため応答冒頭で違いを明示した。
- **tmux 自動起動はできない**: `teammateMode: "auto"` でも、Claude Code を tmux **外** で起動すると in-process モードになる。分割ペイン体験を得るには YD が「`tmux` → `claude`」の順で起動する必要がある。これは仕様 (ターミナル制御の制限)。
- **トークン消費の重さ未検証**: ドキュメントには「メンバー数で線形にスケール」とあるが、Arte Grow 5メンバー深化リサーチで実際にどの程度消費するか未検証。試走後に [[claude_code_agent_teams]] の「コスト感」セクションに実測値を書き残す。

## 📋 次回同じことをするときのチェックリスト

新規 Claude Code 機能 (実験的含む) を導入するとき:

1. `claude --version` でバージョン確認、機能の要求バージョンと突き合わせる
2. settings.json の env セクション有無を確認 → なければ新規追加、あれば key を上書きせずに追加
3. 表示モード (in-process / tmux 分割ペイン) の前提ツール (tmux / iTerm2+it2) が入ってるか `which` で確認
4. tmux インストール: `brew install tmux` (3.6b、依存少、サイズ小)
5. 「サブエージェント」のような曖昧用語は、Claude Code ドキュメント内の正式英名で確認:
   - **subagents** = 既存の軽量委任 (`Agent` ツール、結果のみ返す)
   - **agent teams / teammates** = 実験的、互いに通信可、リーダー+メンバー型
6. 試走は既存リソース (parallel-claude 等が生成した中間成果物) を入力に使うと、ゼロから始めるより議論が深まる
7. 試走後、実測トークン消費を [[claude_code_agent_teams]] に記録 → 次回コスト見積もりの根拠にする
