# API依存撤廃 + Max 20x 完結化への方針転換

## 背景

2026-05-19 朝、YD から指摘:
> APIで動かすAIは極力使わないで欲しい。全てのpjも、APIを使わずとも実現できるシステムを考えて

この指摘は、本AI学習スプリント全体の **根本動機への回帰** を意味する。

### 議論の出発点 (再確認)

会話の冒頭は「Max 20xプラン ($200/月) が使い切れない、消費が10%しか進まない、どうやって使い切るか」。
全ての追加プロジェクト (ai-researcher / morning-briefing / 教科書 / AIシミュレーター / 過去会話インポート / 監視ループ拡張) はこの動機から派生している。

しかし設計フェーズで、Claude (僕) は以下のような有料APIを設計に組み込んだ:
- Anthropic API (要約・分類)
- OpenAI TTS API (音声化)
- Google Cloud TTS (代替案)
- Google Drive API (アップロード) ※OAuth は無料なので継続OK

これは **「Max 20xを使い切る」という根本動機と矛盾する**。Max 20x 外で月$80-100の追加課金が発生する設計だった。

## 意思決定

### 確定事項

1. **API課金が発生する LLM/TTS APIは全廃**
2. **AI処理は全て Claude Code 経由 (Max 20x 枠) で完結させる**
3. **TTS は macOS 標準の `say` コマンドで代替** (Kyoko/Otoya 音声、無料)
4. **書き換えは既存コード流用** (構造・PDFテンプレ・Drive連携は残す、API呼び出し部分だけ差し替え)
5. **教科書システムは現状維持** (API使用なしのため、変更不要)

### 影響範囲

| システム | 現状 | 書き換え後 |
|---|---|---|
| ai-researcher | Claude Haiku 4.5 API + (TTSなし) | launchd → `claude -p` で Claude Code ヘッドレス実行、要約は Max 20x 枠 |
| morning-briefing | Claude Opus 4.7 API + OpenAI tts-1-hd | cron → `claude -p` で生成 + `say -v Kyoko` で TTS |
| textbook-engine | API未使用 (WeasyPrint + Mermaid) | **変更なし** |
| AIシミュレーター | (未実装) | 同じ方針: `claude -p` 経由で複数ペルソナ並列起動 |
| 過去会話インポート | 検索ツールのみ (僕の担当) | **影響なし** (API未使用) |

### 書き換え手順

#### ai-researcher (推定2時間)
1. `src/synthesizer/summarizer.py` の anthropic.Anthropic() を削除
2. 要約処理を `subprocess.run(['claude', '-p', prompt, ...])` 形式に置き換え
3. `.env` から ANTHROPIC_API_KEY 削除、GITHUB_TOKEN は残す
4. launchd plist は変更不要 (collect スクリプトの内部だけ差し替え)
5. 動作確認: `uv run ai-researcher collect` → Vault `raw/research/` に保存されるか

#### morning-briefing (推定3時間)
1. `src/synthesizer/briefing.py` の anthropic.Anthropic() を削除 → `claude -p` 経由に
2. `src/renderer/tts.py` の openai.OpenAI() を削除 → `say -v Kyoko -o tmp.aiff` + `ffmpeg` 変換に置き換え
3. `.env` から ANTHROPIC_API_KEY / OPENAI_API_KEY 削除
4. Drive 連携は OAuth2 なので変更不要 (Drive API 自体は無料)
5. 動作確認: `./run.sh` でフルテスト

### `claude -p` ヘッドレス実行の挙動

Claude Code は `-p "プロンプト"` で1回完結のヘッドレス実行可能。
- 標準出力に応答が出る (パイプで受け取れる)
- ファイル編集は可能 (権限ポリシーに従う)
- 過去の会話履歴は持たない (毎回新規セッション)
- Max 20x 枠で動く (API課金は別途発生しない)

例:
```bash
result=$(claude -p "次の論文を5行で日本語要約してください: $(cat paper.txt)")
echo "$result" > summary.md
```

これで Anthropic API 直接呼び出しを完全に Max 20x 枠で代替可能。

### macOS `say` コマンドの活用

```bash
say -v Kyoko -o briefing.aiff "おはようございます、今日のブリーフィングです..."
ffmpeg -i briefing.aiff briefing.mp3
```

音質は OpenAI tts-1-hd より自然さは落ちるが、日常聞き流しなら十分。
代替: VOICEVOX Engine ローカル (品質高いが構築・運用が面倒) — 将来案として保留。

## ✅ うまく行ったこと

- YDが**設計上の矛盾**を即座に指摘してくれた (寝てる間に作り込まれた直後)
- 撤退判断が早かった (ai-researcher は API key 未設定で稼働していなかった、morning-briefing も .env 未設定で稼働していなかった → 実損ゼロ)
- 教科書システムは API 未使用で組まれていた (セッションA担当者の偶然のファインプレー)

## ❌ 詰まったこと

- **僕 (デスクトップClaude) が設計フェーズで根本動機を見失った**: 「Max 20x 使い切れない」が出発点なのに、API課金前提で指示書を書いた。これは典型的な「LLM処理 = API呼び出し」の業界常識に引っ張られた結果
- Claude Code 5並列を稼働させて作り込んだ後の発覚: 数時間の工数が「書き換え」になった。早期発見できればもっと楽だった
- `claude -p` ヘッドレス実行のベンチマークが未検証: 並列実行時の速度・安定性が API 直接呼び出しと同等かは未確認
