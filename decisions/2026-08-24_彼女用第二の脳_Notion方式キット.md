# 彼女用「第二の脳」を Notion 方式で移植するキットを作成

YD の Obsidian Vault 方式 (Claude の外部記憶) を、彼女の Claude Pro アカウントで同じように動かすための移植キット。前提: iPhone がほぼ唯一の端末、非エンジニア、ChatGPT からの移行、普通の質問には即答してほしい。

## 状況と選択肢

Claude の iPhone アプリはローカルファイルを読めないので、Obsidian + Desktop Commander 方式は成立しない。外部記憶をクラウドに置き、コネクタで読み書きさせる必要がある。候補は Notion (コネクタ公式、彼女が iPhone で見られる、YD が保守できる) / GitHub 直 (Markdown 構造が Vault と同一だが非エンジニアが GitHub を開く場面がない) / Claude 内蔵のみ (Projects + メモリ。書き戻し先がなく decisions・mistakes・log が消える)。Notion を採用。YD は「お任せ」。彼女は Notion アカウント既存。

プラン面: Enterprise は最低20席 (営業経由は50席) で二人では契約不可。Team は最低2席で年480ドル、Pro×2 年払いで年400ドル。YD は Max のまま、彼女は Pro 単体契約で決着。

## 設計

Notion「第二の脳」の中に、00_起動 (憲法 + 起動手順 + 各ページへのリンク) / わたし (identity) / いま (current_state) / Claudeのミス記録 (mistakes) / 決めたこと DB (decisions、5見出し) / ノウハウ DB (knowledge、5見出し) / ログ / アーカイブ。起動は Preferences のトリガー語 (おはよう等) か、Project「第二の脳」の指示文で自動。保存・ミス記録のルールは 00_起動 にだけ置き、Preferences と Project 指示文は「いつ 00_起動 を読むか」しか書かない (ルール変更が Notion 直編集で完結する)。彼女の応答スタイルは最初のプロンプトのインタビューで本人が決める。固定で入れたのは「普通の質問は即答、リサーチ・文書作成・比較検討・計画だけじっくり」のみ。

成果物: `~/Downloads/second-brain-kit/` の6ファイル (00_README_手順 / 01_ChatGPTメモリ移行 / 02_Preferences貼り付け文 / 03_最初のプロンプト / 04_Project指示文 / 05_使い方)。03 はファイル全体がそのまま貼る文面で、Notion 構築 → 2回のインタビュー → 書き込み → Preferences 追記文と Project 指示文 (URL 入り) の出力まで自走する。

## ✅ うまく行ったこと

- 彼女の環境を聞いてから設計を変えた。最初の案 (Obsidian + Desktop Commander) は「iPhone がメイン」の一言で崩れたので、AskUserQuestion で PC 環境・用途・範囲・納品形態を先に確認したのが効いた
- サブエージェントの敵対的レビューで12件の欠陥が出た (インタビューがプロフィール事実を聞いていない / 検索に頼る起動が新規ページのインデックス遅延で失敗する / 「1回でまとめて聞け」と2回インタビューの矛盾 / Preferences に保存ルールを複製すると 00_起動 だけ直せば済まなくなる / 「毎回必ず読む」がメッセージごとの読み込みに解釈される / ログに時刻を要求しても Claude は時刻を持たない 等)。全部潰してから納品した
- 公式ヘルプの確認で前提を修正できた: コネクタは Web で接続すれば iOS でも使える、カスタムスキルは全プランでアップロード可、メモリインポートは 設定 > メモリ (Web/Desktop のみ、実験的機能)

## ❌ 詰まったこと

- zip を base64 化して Desktop Commander の write_file 1回で Mac に転送しようとして CRC エラー。17KB の base64 をツール引数で書き写すのは無理だった。結局 write_file の分割書き込み (≤50行) で6ファイルを送り、md5 で全一致を確認した。詳細は [[tool_usage_mistakes]]
- Vault の decisions は必須3セクションの見出しに絵文字を使う既存規約で、hikizan (絵文字ゼロ) と衝突する。本ファイルは Vault 規約を優先した。規約をどちらに寄せるかは未決 → [[open_questions]] 候補

## 📋 次回同じことをするときのチェックリスト

1. 移植先の人の「メイン端末」を最初に聞く。iPhone 中心ならローカルファイル方式は選択肢から外し、Notion / Drive などコネクタ経由の置き場に切り替える
2. ルールは1か所 (Notion の 00_起動 相当) にだけ置き、Preferences / Project 指示文には「いつ読むか」だけ書く。複製すると保守が2倍になる
3. 起動時の読み込みは4ページ程度に絞る (Pro の使用量と iPhone の待ち時間)。decisions / knowledge は必要時に検索
4. 自走プロンプトは「途中で切れた時に最後の出力が出ない」ので、末尾の目印 (「の3つです。」で終わる) を手順書に書いて確認させる
5. Mac へのファイル転送は write_file 分割 + md5 照合。base64 経由はしない
6. 納品前にサブエージェントの敵対的レビューを1回入れる (今回は12件出た)

## 追記 (2026-08-24 同日): 全自動保存に変更

YD 指示「どんな状態であれ会話から得られる情報は全部全自動で保存」。合図語 (これ覚えといて / 今日はここまで) 依存をやめ、どの会話でも新しい情報が出た返事の中で Notion に書く方式に変更。設計上のポイントは、00_起動 は起動した会話でしか読まれないので「合図なしで保存する」という動きだけ Preferences (全会話で読まれる) に置き、保存先・書き方の詳細は 00_起動 に残したこと。加えて、保存前に保存先ページを読んで重複を避ける、返事の本文を先に書いて保存は末尾に回す (即答の体感を守る)、起動時にメモリと Notion の差分を Notion に書く (取りこぼし回収) を入れた。限界は「Claude が動くのは本人がメッセージを送った時だけ」の1点で、返事ごとに保存するためアプリを閉じても直前の返事までは残る。キットは 02 / 03 / 05 / 00 を更新し、Mac の ~/Downloads/second-brain-kit/ と md5 一致を確認済み。
