# PAA 白基調リデザイン確定 (2026-08-08〜09)

YD 指示「フロントエンドも改良したくて、アプリの全ページを Claude Design にデザイン面を作り直してほしい」
+ 途中で「背景色はやっぱ白に統一したいな」+「UI・UX を超使いやすく、超見やすく、スッと情報が入るように」。

## 選んだ方針

**claude.ai/design を Chrome 自動操作で実際に駆動し (YD 指示「Chromeで自動でバンバン操作しちゃって」)、
Fable 5 / Effort Max で全41画面を生成する。**

視覚の正 = https://claude.ai/design/p/2235e024-afb8-4600-80dc-afc6fd6dca0c

## 確定した文法 (YD が3案から選択)

まず「白地で階層をどう作るか」を設計の中心命題として投げ、3案を出させた:

| 案 | 原理 |
|---|---|
| 1a 線と余白 | 面を作らず罫線と帯だけで区切る。iOS 標準に最も近い |
| 1b 青の帯 | 画面の頭の青帯が「現在地」と「まず何をするか」を宣言。最もブランドが強い |
| 1c 沈む面とキー | グループが沈み、押せるものだけが白いキーとして浮く。最も操作が分かりやすい |

→ **YD 選択 = 1b をベースに 1c を統合**。

- 地は白 `#FFFFFF`、沈み面 `#F5F6F8`。**クリーム `#FFF8DC` は完全撤廃**
- 青 `#025291` の帯が現在地とハルの指名。橙 `#FF8B07` は主アクションと締切のみ
- **押せるもの = 沈んだ面から1段浮いた白いキー** (1px境界+硬い1px影)、押せない情報は面に直置き
- ダーク例外は **振り返り一覧 / 年次Wrapped / お宝箱撮影** の3つのみ (ダイジェスト詳細は白)

## YD フィードバックで確定した仕様

1. **ホーム**: 見出しは「今日やること」のみ。件数は小さなメタへ
2. **タスク詳細**: 上から 青帯(締切チップ1本) → 概要 → 提出 → コメント → 担当・チーム。
   「担当・期限・チーム」の3行ブロックを上から撤去。提出欄を主役化し「完了にする」を内包
3. **★ コピーの語調**: 「小学生に対する言葉遣い」は NG。**ターゲットは大学生と社会人**。
   名詞・体言止め基本、幼い語尾・絵文字・演出過剰を排除。ハルの発話も対等なトーン。
   (つくっているよ→作成中 / 新しい団体をつくる→団体登録)

## ✅ うまく行ったこと

- **「白地で階層をどう作るか」を設計課題として明示的に投げたこと**。放っておけば
  「白背景に白カード + 薄いグレーの影」= SaaS テンプレの AI スロップに落ちる領域だったが、
  3案とも別々の原理で解いてきた。**課題を名指しすると質が上がる**
- **事前に移行調査を並行で走らせたこと**。tokens.ts の alias 構造のおかげで 164 箇所が
  1ファイルで追従すると分かり、同時に「白地で不可視化するカード」を実測で24箇所特定できた。
  設計課題が机上でなく実コードの実害だと裏付けられた
- **語調ルールを生成の途中で投入したこと**。全部できてから直すより安く、
  画面集5以降は最初から正しい語調で生成された
- Claude Design が**自分で罠を見つけて直した** (safe area の原因が「ルートが content-box で
  中身が64px内部スクロールできる構造」だと特定)。実装時の落とし穴として記録できた

## ❌ 詰まったこと

- **Claude Design の入力欄は Enter で送信される**。改行を含むテキストを `type` したら
  行ごとにバラバラ送信された。長い指示は**改行なしの1行**で打つ必要がある
- ウィンドウがリサイズされた際に**入力欄の内容が消えた**。送信前に必ずスクリーンショットで確認する
- 生成が**セット単位で止まる**。「次のターンで画面集4へ進みます」で待機するので、
  最初から「途中で止まらず画面集6まで一気に」と指示すべきだった

## 📋 次回同じことをするときのチェックリスト

1. Claude Design を使うなら、**モデルと Effort を最初に設定** (Model ドロップダウン → Fable 5、Effort → Max)
2. 入力は**改行なしの1行**で。長文でも改行を入れない
3. 送信前にスクリーンショットで**入力欄の中身が残っているか確認**
4. 「途中で止まらず最後まで一気に」と最初に指示する (セット単位で待機してしまう)
5. **設計の核心課題を名指しして投げる**。「白地で階層をどう作るか」のように、
   放置すると凡庸に落ちる部分を明示すると案の質が変わる
6. コピーの語調ルールは**生成の早い段階で**入れる (後追い修正は全画面分のコストになる)
7. デザイン生成と並行して**既存コードへの波及調査**を走らせる。実装コストと壊れる箇所が先に分かる

## 実装時の必須事項 (未着手)

- **`tokens.ts` の反転と「カードの型」適用は同一コミット必須**。分割すると地もカードも白で階層が崩壊する
- 白地で不可視化するカード: パターンB (影のみ依存・16箇所) + パターンC (枠線も影もなし・8箇所)
- MOCK モード保全は絶対 (友達 TestFlight デモ)
- 検証ゲート = tsc 0 / eslint 0 / jest / シミュレータ実表示
