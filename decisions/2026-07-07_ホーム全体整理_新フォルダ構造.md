## 体制

Fable 5 が全域スキャン→構造設計→AskUserQuestionで4決定 (ALL WORKs命名 / ゴミは移動のみ / スクショ保存先変更 / GO) → **Sonnet 5 ×3並列** (Desktop担当・DL素材担当・DL書類担当) が実装、各自TSVログ→Fableが検収・統合。

## ✅ うまく行ったこと

- 3並列でも衝突ゼロ: 担当領域をファイル種別で分離 (素材系 vs 書類系)、各agentが mv 前に `ls -d` 実在確認 → 他担当が先に動かした3件も正しくスキップされた
- 「移動のみ・削除ゼロ・全件TSVログ」の規律で、582件動かしてもデータ消失リスクゼロ (前回 reorg_moves_v2.tsv と同じ方式)
- リネーム+互換symlinkの組み合わせで、アプリのパス参照を壊さず名前だけ改善できた
- スクショ保存先のOS設定変更 (`defaults write com.apple.screencapture location`) で再発防止までワンセット化

## ❌ 詰まったこと

- **iCloud Desktop&Documents同期が有効**: 大きいフォルダ/動画を同時に mv すると fileproviderd の処理待ちで数分〜完全ハングする。1件ずつ順番に実行して解消 (データ消失なし、mv完了までは移動元に残る仕様)
- ハングした mv を kill した際、agent の自作ログ関数が「移動成功」と誤記録した箇所が1件 → ファイル実態と突き合わせて修正。**ログは書いた後に実態とクロス検証が必須**
- Sonnet agent 2体が「削除禁止」ルールの文言に反して空フォルダ/自分の一時ファイルを削除 (実害ゼロ、自己申告あり)。ルールに「空フォルダも移動」と明記すべきだった
- 科目フォルダの重複 (`債権総論` と `債権総論 2` 等): 複数ソースから同名フォルダが集まる場合の衝突。検収パスで統合した

## 📋 次回同じことをするときのチェックリスト

1. 既存の整理資産を先に読む (`MAP.md` / `MediaCatalog/` / 過去の整理ログ) — 二重整理・規格の不一致を防ぐ
2. リネーム対象を参照しているもの (編集アプリのプロジェクト・HANDOVER・スクリプト) を洗い出し、互換symlinkで逃がす
3. 並列agentは「ファイル種別 or 場所」で担当を完全分離 + 各自 `ls -d` 実在確認 + 担当別TSVログ → 最後に統合
4. iCloud同期フォルダ (Desktop/Documents) の mv は1件ずつ。ハング時に kill したら必ずログと実態を突き合わせる
5. 削除は絶対しない。「_ゴミ候補」「_要確認」に集めてYDの一括判断に回す
6. 仕上げ検収で「残骸 (空フォルダ・重複フォルダ)」を必ず一周確認する
7. メモリ (`media-organization-project.md`) と MAP.md の更新まで含めて完了
