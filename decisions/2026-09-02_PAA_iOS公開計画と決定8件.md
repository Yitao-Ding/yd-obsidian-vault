# PAA を iOS App Store に公開する計画と、YD の決定 8 件

## 状況

YD「もういい加減にそろそろ公開したい」(2026-09-02)。TestFlight には MOCK デモしか出ておらず、実モードで一般ユーザーが使える状態ではなかった。64 エージェントの公開監査 (7 次元の読者 → Fable の反証 → 計画合成) で公開ブロッカー 41 件を 7 束に整理し、`project-agent-application/RELEASE_PLAN_2026-09.md` に計画を書いた。提出目標 9/6、公開 9/8〜9、差し戻し込み 9/12。

主な事実: Supabase 実 DB が 2 回目の pause (Free 枠、無活動 7 日) / Supabase Auth の site_url が別プロジェクトのまま、Apple・Google プロバイダ未設定、custom SMTP なし (2 通/時) / アカウント削除・UGC 通報が未実装 (審査必須) / ドメイン projectagent.app 未取得 / Storage upload が RN iOS で空 part になるバグ (demo ビルドは upload をスキップしていたので未発見)。

## 決定 (YD 回答 2026-09-02)

- ログインは メール + Apple + Google + LINE の 4 種 (推奨は 2 種だったが YD が 4 種を選択)
- メールは 6 桁コード (Magic Link のリンクも両対応)
- projectagent.app を Cloudflare で購入 (約 2,500 円/年)
- 運営者表記は「Yitao Ding」のみ + support@projectagent.app
- Supabase は Free + keep-alive (GitHub Actions 6 時間毎 + UptimeRobot 5 分毎)、ユーザー 50 人か 1 か月で Pro
- Gemini は GCP 課金を有効化 (学習利用なし)
- アイコンは app-icon-options.svg 案 1 (Horizon)
- Expo SDK 56 のまま出す。57 + expo-updates + Sentry は 1.0.1
- v1 は iPhone 専用・日本語のみ、Android は公開後
- (同日夜に追加) マスコット (ハル / Finch / お掃除演出 / キャラ名カスタマイズ / キャラ名義の通知) を v1 から撤去する。「あまり影響ない範囲で」= 画面骨格と機能は残し、見た目と文言だけ素の UI に置換。DB 列は残す。Claude Design の Round 2 (2a〜2f) は採用せず終了

## うまく行ったこと

- 監査を「読者 (opus) → 反証 (fable) → 完全性チェック → 計画合成」の 4 段にしたことで、誤った主張 (022 を今すぐ適用可、など) が計画に混ざらなかった
- builder (opus) 3 便 + Fable 検収 + 合流ゲートで、決定を待たずに 5 タスクを同日中に Pass まで持っていけた
- YD の手作業を「今日の決定 / 明日の一括セッション / 提出日の ASC 入力」の 3 回にまとめ、貼り付け値を `RELEASE_DAY1_YD.md` に先に書いた

## 詰まったこと

- Supabase Free の pause は警告メールが機能せず、8/23 と 9/2 の 2 回とも実測で気づいた。keep-alive と外部監視を提出前に入れる
- リポジトリが PRIVATE のため GitHub Pages が使えず、法的ページは Cloudflare Pages に統一
- LINE ログインはメール取得権限の審査に日数がかかる。提出までに下りなければ LINE だけ 1.0.1 に回す前提で進める

## 次回同じことをするときのチェックリスト

1. 公開前に Supabase Auth の site_url / redirect / providers / SMTP を Management API で実測する (ダッシュボードの自己申告や過去の HANDOVER を信じない)
2. Storage upload は demo ビルドで検証できない (MOCK がスキップする)。実モードの TestFlight で必ず 1 件アップロードする
3. 審査員のログイン手段 (パスワード経路 + 審査用アカウント) を先に作る。Magic Link 専用だと審査員はメールを受け取れない
4. 個人開発の App Store 提出は、ドメイン → SMTP → プロバイダ → ビルド の順に依存があるので、ドメイン購入を最初にやる
