## 入力素材

- `transcript.md` — タイムスタンプ付き字幕(発信者の発言、主素材)
- `scenes.md` — シーン分割情報
- `frames/` — 各シーン代表フレーム画像(146枚)。**コードエディタ・ブラウザ・ターミナル・図解**が映っているフレームを重点的に確認

## 進め方(4ステップ、確認なしで通して進めて構わない)

### Step 1. 題材と最終成果物の把握

`transcript.md` を頭から読みつつ `frames/` を走査し、以下を 200 字以内で `BRIEF.md` に書き出す:

- **題材**(例: Next.js + shadcn でランディングページを作る / Python で OAuth クライアント実装 / FFmpeg で動画前処理 など)
- **想定スタック**(言語・フレームワーク・ライブラリ。frames のエディタ画面・package.json・import 文から推定)
- **最終成果物**(動画ラスト付近の frame が完成形を示すことが多い)
- **対象読者の前提知識**(初心者向け / 中級向け など)

### Step 2. 手順書 `TUTORIAL.md` 作成

字幕とシーンを論理的なステップに分割し、各ステップを次の形で記述:

```markdown
## Step N. <短いタイトル>

- 時刻: HH:MM:SS – HH:MM:SS
- 参照フレーム: ![[frames/00XX_HH-MM-SS.jpg]]
- 目的: <そのステップで何を達成するか、1〜2文>
- 操作内容: <発言抜粋を踏まえた具体的な手順>
- コード/コマンド(該当すれば): <該当フレームから読み取れた範囲>
```

ステップ数は動画の論理構造に従う(機械的に時間で切らない)。
コードや CLI 操作が出てくるステップは、frames を文字起こしする要領で **可能な範囲で正確に書き起こす**。

### Step 3. 実装

このフォルダ直下に `code/` ディレクトリを作って実装する。

- `TUTORIAL.md` のステップを上から順に実装
- 各ステップ完了時に必ず動作確認(`pnpm dev` / `python -m ...` / `cargo run` 等、スタックに応じて)
- frames から読み取れない箇所(打鍵されたコードが映ってない、字幕も抽象的)は推定で補完し、その箇所を `IMPLEMENTATION_NOTES.md` に「動画から確実に取れた箇所」「自分で推定した箇所」に分けて記録
- 動画と異なる選択をした場合(ライブラリのバージョン、命名)も `IMPLEMENTATION_NOTES.md` に明記

### Step 4. 自己評価 + Obsidian 用要約

最後に以下 2 つを書き出して終了:

- `IMPLEMENTATION_NOTES.md` — 実装中の判断・推定・残課題
- `REPORT.md` — Obsidian 取り込み用要約(YAML frontmatter 付き、tags: [tutorial, 動画学習, 実装])
  - 動画から学んだこと TOP 3
  - 詰まった点と解決方法
  - 動画では触れられなかったが実装してみて分かったこと
  - 次に試したい派生実装

## 重要な原則

- **動画通りにできない箇所で止まらない**。動画は環境やバージョンが古いことがあるので、より新しい代替で実装してOK(その差分を NOTES に記録)
- **完成形を優先**。文字起こしの一字一句より、frames の最終画面に近づけることを優先
- 既知の API キーやシークレットが必要なら `.env.example` を作り、`README.md` に取得手順を書く

開始してください。確認質問は不要、進めて構いません。
