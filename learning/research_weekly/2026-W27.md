## 必読 1 本

**「Claude Code Just Got 5x More Expensive」**

YD が日常的に使っている Claude Code の実効コストが前週比で 83% 削減という形で激変した、という実測分析。サブスク料金は変わらないのにトークン枠が 16–17% に圧縮され、しかもキャッシュ生成・内部リトライ等の隠れ消費がログに出ない。マルチターンエージェントワークフローでは予測不可能なコスト爆増が発生しうる。今週の Claude Code 関連3記事の中で実運用への影響が最も即時かつ具体的なため、まずこれを読むべき。

## YD が今週試すべき1つ

**mcpsnoop を lecture_hub の MCP 通信に噛ませて、ボトルネックを計測する。**

`brew install` または `cargo install` で入れて、既存の MCP サーバーとクライアントの間に透過プロキシとして挟むだけで即起動できる。レスポンスタイムとペイロードサイズが TUI で見えるようになるため、「どのツール呼び出しが遅いか」が半日以内に数字で把握できる。Claude Code のコスト問題が顕在化している今週、通信コストの実態を把握しておく意味は大きい。

## 既存プロジェクトとの接続

- **lecture_hub**: Claude Science の MCP 連携アーキテクチャがそのまま参考になる。論文自動取得 → 分類 → ブリーフィング生成のパイプラインを組むうえで、Claude Science の設計思想は直接転用できる。mcpsnoop でMCP 通信を可視化しておくと統合デバッグが楽になる。AskUserQuestion のタイムアウトバグは自動ワークフロー中の確認ステップに影響する可能性があるため、v2.1.198 を使っている場合は確認要。
- **vidkit**: Alibaba 禁止報道・ステガノグラフィ疑惑ともに Claude Code への依存リスクとして認識しておく価値がある。今すぐ移行判断する必要はないが、代替ワークフローを一つ持っておくと安心。
